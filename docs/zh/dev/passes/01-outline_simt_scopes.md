# OutlineSimtScopes

`OutlineSimtScopes` 将显式 AIV 函数中的临时 `SimtScopeStmt` 提取为返回 void 的
`FunctionType.SIMT` helper 和 `SimtLaunchStmt`。它位于 `InlineFunctions`、控制流
规范化、SSA 转换及 scope 展平之前。代码生成拒绝尚未提取的 scope。

## 捕获与结果

按首次词法使用顺序和 Var 身份捕获变量。helper 使用新参数，并将函数体中的外层
引用替换为这些参数。运行时标量是所有线程共有的输入；标量重新赋值创建线程私有
绑定，不修改调用方。线程私有值不能逃逸。

临时节点通过 `private_scalars` 记录被重新赋值的外层标量绑定。这些是对调用方绑定
的使用，而非定义。克隆保留初始值，并避免 region 内赋值影响调用方后续引用；
仅在单个分支中执行的标量赋值也遵循该规则。

即使 store 位于条件分支中，被写入的存储参数也推导为 `InOut`。每个可写参数按参数
顺序对应一个 launch 结果。在 SSA 前，该结果定义外层捕获绑定；SSA 随后创建新的
存储版本。现有 Tile 输出物化保留旧别名及未写元素；Tensor 别名继续引用同一 GM。

外层 `In` 权限通过句柄复制和视图传播。捕获的存储必须已初始化。完整、无掩码的
覆盖式 `tile.store` 可在捕获前初始化 `Out` Tensor；部分写入或条件写入不能证明后续汇合点
已初始化。原子存储会读取目标的旧值，不能建立初始化证明。在同一分支中，初始化之后的 scope 可以使用该事实。

当无法证明来源时，拒绝捕获函数调用返回的存储或从重新绑定的元组中提取的存储。
元组存储投影也不能为循环初值或 yield 提供初始化证明，包括嵌套在 Tile 算术中的
投影：源变量重新绑定后，元组可能仍保留旧句柄。应改为捕获或携带原始命名存储。
初值、yield 和赋值中的视图表达式继承源存储权限，包括嵌套视图；新产生的 Tile
算术结果保持独立的存储权限。

初始化事实跟随当前存储值，并与保守的别名权限分析分开。完整写入只证明确定的
目标及其别名已初始化；新的 Tile 加载会替换先前未初始化的值，但不会初始化旧别名。
分支内的证明及发生变化的存储身份不会在汇合点后被直接采用。循环捕获还必须在
后续迭代中保持已初始化；捕获前的新加载可以提供新的证明。SIMT scope 内的 JIT
形状常量折叠和标量重命名不会影响后续调用方代码。区域内保留可能被条件分支重新绑定的私有标量赋值，包括来自形状的赋值。
顺序重新赋值会在计算右侧表达式后使旧的常量折叠失效。
形状赋值（包括解包）会更新当前标量绑定，即使先前的重新赋值已为它生成新的内部名称。
若私有变量写入前可能读取传入的形状常量，则先将该常量物化为标量，从而正确处理
条件写入前的原值和后续的新绑定。`if` 两个分支均从传入绑定开始，变化的绑定在汇合点
仍失效。显式循环携带值保留初值的初始化证明；依赖这些值的捕获要求每次迭代的
yield 值均已初始化。只有初值和回边值都已初始化时，循环输出才具有初始化证明。
初值和 yield 表达式在调用展平前接受检查，包括嵌套 Tile 算术。先计算所有回边的
初始化状态，再验证相关要求，避免携带值之间的依赖因参数顺序而漏检。
SIMT 内的形状解包始终展开为标量，即使条件写入要求保留运行时绑定。

## 合法性与资源

初期仅支持显式 AIV 函数。拒绝嵌套 SIMT、活跃 register scope、helper 内分配或重新
绑定存储、捕获 VMI 寄存器以及跨 region 跳转。生成的 helper 由规范 SIMT verifier 校验。

维度必须是三个编译期正整数，与显式 launch 共用目标资源校验；后续特化填入线程数
和寄存器上限，用户不能覆盖这些资源参数。

每个函数只索引一次 region 定义和存储权限；捕获收集遍历互不重叠的 region。
别名采用按秩合并和路径压缩，命名使用有序集合，总复杂度为 O(N log N)。

公共语法见 [SIMT 编写与 IR](../ir/11-simt.md)，流水线见 [Pass 管理器](00-pass_manager.md)。

## OutlineRegScopes

`OutlineRegScopes` 紧接 `OutlineSimtScopes`，位于 `InlineFunctions`、SSA 转换和
`ExpandMixedKernel` 之前。它把每个 `RegScopeStmt` 提取为同步的 `FunctionType.VF`
辅助函数，并在原位置生成普通函数调用。辅助函数保留寄存器作用域，因此寄存器、
掩码和硬件循环仍具有明确的词法归属。VF 是设备辅助函数，不是独立调度的 kernel，
也不能作为 `Submit` 的目标。

```python
# Before
with pl.reg_scope():
    x = pl.reg.load(src, lanes=64)
    out = pl.reg.store(dst, value=x)
z = pl.tile.add(out, out)

# After (the compiler adds kernel_vf_0 to the Program)
out = self.kernel_vf_0(src, dst)
z = pl.tile.add(out, out)
```

捕获按 Var 身份和确定的首次使用顺序排列，Tile 形状及 view 表达式中的符号也会成为
Scalar 捕获。参数复用现有的 `In`/`InOut` 方向；store 的目的参数为 `InOut`。
返回的 Tile 别名通过函数的返回契约关联到捕获参数。寄存器和作用域内的局部 Scalar
不能跨越函数边界。没有外部使用的返回值时仍生成调用，保留 store 的写副作用。

`ExpandMixedKernel` 将 VF 调用放在 AIV。Tile 存储仍归 caller 所有，`InitMemRef`
通过现有返回来源分析关联返回别名，VF helper 不单独分配内存。VF 的 `InOut`
表示借用存储，不使 caller 的原 Tile handle 失效。寄存器初始化检查使用 caller
的实际存储绑定分析 helper，不把 `InOut` 当作整个 Tile 已初始化的证明。

包含源寄存器作用域的程序在捕获分析前完成普通 Inline 展开。这不仅特化包含作用域的
模板和包装函数，也在常量传播前显露不含作用域的标量生产函数及标量 `Out` 写入。
已消费的 Inline 声明全部删除；没有源寄存器作用域的程序仍保留普通内联阶段。
调用方仍必须在 `Out`/`InOut` 调用后使用返回值，输入验证器继续执行该契约。

已证明的调用方常量在捕获参数隐藏其值之前传播到作用域中；helper 规范化在检查返回别名
之前折叠常量分支。VF 绑定常量实参后也会消除已证明的分支及零次或单次迭代循环，
保留副作用、yield 值和返回别名。非空且显式要求硬件循环的结构保留其策略。
依赖运行时条件的分支仍受现有后端限制。

PTO codegen 将显式 helper 参数绑定到最终 caller 实参，复用已有寄存器发射器和
带 effects 注解的 Tile adapter。每个执行调用使用与其 UB 偏移匹配的产物。
现有执行能力限制保持不变，提取 pass 不添加同步。

提取时先用现有循环展开和 SSA 转换器规范化新 helper，再推导参数方向和返回别名，避免源码变量重新赋值改变较早结果的存储身份；调用方仍处于前端阶段。捕获顺序遵循首次使用顺序，但 Tile 类型引用的标量符号必须先于该 Tile 参数声明。
条件重新赋值会保留传入的捕获值，包括循环执行零次时的值。Tile 分支结果和循环携带值
在所有可达路径上必须指向同一个捕获存储。已证明的调用方常量会在检查契约前选择分支；
运行时在不同缓冲区之间选择仍被拒绝。

固定 VF 捕获列表前，提取器展开寄存器作用域内的 Inline 调用，并代入外层静态展开循环的
索引。这会移除 VF ABI 中未使用的 Tensor 或尚未指定内存空间的 Tile 参数，同时保留
依赖调用方索引的内层展开边界，包括在各调用点特化的只读 Inline 参数。ND 借用 Tile
的参数、别名和返回类型一起展平；元组别名经过复制、重复投影和返回相同存储的分支汇合后，
仍引用调用方存储。
