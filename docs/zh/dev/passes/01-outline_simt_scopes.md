# OutlineSimtScopes

`OutlineSimtScopes` 将显式 AIV 函数中的临时 `SimtScopeStmt` 提取为返回 void 的
`FunctionType.SIMT` helper 和 `SimtLaunchStmt`。它位于 `InlineFunctions`、控制流
规范化、SSA 转换及 scope 展平之前。代码生成拒绝尚未提取的 scope。

## 捕获与结果

按首次词法使用顺序和 Var 身份捕获变量。helper 使用新参数，并将函数体中的外层
引用替换为这些参数。运行时标量是所有线程共有的输入；标量重新赋值创建线程私有
绑定，不修改调用方。线程私有值不能逃逸。

临时节点通过 `private_scalars` 记录被重新赋值的外层标量绑定。这些是对调用方绑定
的使用，而非定义。克隆保留初始值，并避免 region 内赋值影响调用方后续引用；
仅在单个分支中执行的标量赋值也遵循该规则。

即使 store 位于条件分支中，被写入的存储参数也推导为 `InOut`。每个可写参数按参数
顺序对应一个 launch 结果。在 SSA 前，该结果定义外层捕获绑定；SSA 随后创建新的
存储版本。现有 Tile 输出物化保留旧别名及未写元素；Tensor 别名继续引用同一 GM。

外层 `In` 权限通过句柄复制和视图传播。捕获的存储必须已初始化。完整、无掩码的
`tile.store` 可在捕获前初始化 `Out` Tensor；部分写入或条件写入不能证明后续汇合点
已初始化。在同一分支中，初始化之后的 scope 可以使用该事实。

当无法证明来源时，拒绝捕获函数调用返回的存储或从重新绑定的元组中提取的存储。
应改为捕获原始命名存储。

初始化事实跟随当前存储值，并与保守的别名权限分析分开。完整写入只证明确定的
目标及其别名已初始化；新的 Tile 加载会替换先前未初始化的值，但不会初始化旧别名。
分支内的证明及发生变化的存储身份不会在汇合点后被直接采用。循环捕获还必须在
后续迭代中保持已初始化；捕获前的新加载可以提供新的证明。SIMT scope 内的 JIT
形状常量折叠和标量重命名不会影响后续调用方代码。区域内保留可能被条件分支重新绑定的私有标量赋值，包括来自形状的赋值。
顺序重新赋值会在计算右侧表达式后使旧的常量折叠失效。
若私有变量写入前可能读取传入的形状常量，则先将该常量物化为标量，从而正确处理
条件写入前的原值和后续的新绑定。`if` 两个分支均从传入绑定开始，变化的绑定在汇合点
仍失效。显式循环携带值保留初值的初始化证明；依赖这些值的捕获要求每次迭代的
yield 值均已初始化。只有初值和回边值都已初始化时，循环输出才具有初始化证明。
初值和 yield 表达式在调用展平前接受检查，包括嵌套 Tile 算术。先计算所有回边的
初始化状态，再验证相关要求，避免携带值之间的依赖因参数顺序而漏检。
SIMT 内的形状解包始终展开为标量，即使条件写入要求保留运行时绑定。

## 合法性与资源

初期仅支持显式 AIV 函数。拒绝嵌套 SIMT、活跃 register scope、helper 内分配或重新
绑定存储、捕获 VMI 寄存器以及跨 region 跳转。生成的 helper 由规范 SIMT verifier 校验。

维度必须是三个编译期正整数，与显式 launch 共用目标资源校验；后续特化填入线程数
和寄存器上限，用户不能覆盖这些资源参数。

每个函数只索引一次 region 定义和存储权限；捕获收集遍历互不重叠的 region。
别名采用按秩合并和路径压缩，命名使用有序集合，总复杂度为 O(N log N)。

公共语法见 [SIMT 编写与 IR](../ir/11-simt.md)，流水线见 [Pass 管理器](00-pass_manager.md)。
